# 대규모 K-Means 군집화는 오프라인 배치로 중심점을 구하고, 실시간 서빙은 1-NN으로 초고속 분류한다

## 🤔 헷갈렸던 점
- K-Means로 유저들을 군집화하고, 신규 유저가 들어왔을 때 가장 가까운 중심점(1-NN)에 할당했던 과거의 실무 방식이 빅데이터/AI 관점에서 정석적이고 유효한 패턴인지 궁금했다.

## ✅ 정리
- **표준 2-Tier 머신러닝 아키텍처 (오프라인 학습 + 온라인 서빙)**:
  - 과거 방식은 데이터 엔지니어링 및 AI 분야에서 **가장 교과서적이고 이상적인 정석 패턴**이라고 한다.
- **연산량의 혁신 ($O(N) \rightarrow O(K)$)**:
  - 1,000만 명 전체 유저와 거리를 일일이 비교하면($O(N)$) 신규 유저 1명 들어올 때마다 서버가 멈춘다.
  - 하지만 **K-Means로 미리 대표 중심점 $K$개(예: 10개 페르소나)만 계산해 두면**, 신규 유저는 **오직 10개의 중심점과만 거리를 계산($K=1$, 1-NN)**하면 끝난다.
  - 연산 시간이 **0.0001초(밀리초 이하)**로 단축되어 실시간 API 서빙이 가능해진다.
- **ML 라이브러리의 표준 동작**:
  - Scikit-learn이나 PySpark의 `kmeans_model.predict(new_data)` 역시 내부에서 정확히 **중심점들과의 최단거리(1-NN)를 계산**하여 군집 번호를 할당한다.

### 💡 실사용 예시: 배치 학습과 실시간 1-NN 서빙 흐름
```
[새벽 오프라인 배치 (Spark K-Means)]
 수천만 로그 분석 ──▶ 3개의 핵심 페르소나 중심점 도출 (알뜰형, 트렌드형, 프리미엄형)

[실시간 온라인 서빙 (1-NN)]
 신규 유저 접속 ──▶ 3개 중심점과의 거리만 즉시 계산 ──▶ "알뜰형 중심점과 최단거리!" ──▶ 맞춤 쿠폰 즉시 발급
```

**"무거운 연산은 오프라인 배치(K-Means)로 중심점만 뽑아두고, 실시간 서빙은 중심점 기반 1-NN으로 가볍게 끝내는 것"**이 빅데이터 AI 서빙의 표준이다.
